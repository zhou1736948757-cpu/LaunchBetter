## Findings

### F1 — Important: tracking-only teardown is flushed as `settled`
`PagingInteractionController.isEnabled = false` and `shutdown()` emit `.cancelled(nil)` only when `phase == .settling` (PagingInteractionController.swift:115-128, 155-167). `jumpTo()` has the same settling-only lifecycle callback (552-571). If the controller is in `.tracking`, these paths transition to idle and call `onPhaseIdle`, but do not invoke `onInteractionCancelled` or otherwise mark cancellation. GridViewController's `onPhaseIdle` then calls `flushCompositorActivationTelemetry()` with its default `.settled` reason (GridViewController.swift:1386-1389). Thus an active horizontal telemetry session can be reported as `completionReason=settled` for disable/shutdown/jump, violating T-008 required cancellation semantics for those paths. The existing lifecycle test only starts a settle (PagingLifecycleTests.swift:66-85), so it cannot detect this tracking case.

Required correction: make each teardown path explicitly cancel any active tracking telemetry session too (or centralize a teardown lifecycle callback), with an actual behavior test for tracking + shutdown, tracking + disable, and tracking + jump; preserve flush-once behavior.

### F2 — Test coverage gap: cancellation/NSEvent behavior is not end-to-end for telemetry
`PageCompositorActivationTelemetryTests` verifies nil duration and flush-once at the telemetry object level, while `PagingLifecycleTests` verifies cancellation callbacks only for an active settle. There is no behavior test wiring a real active horizontal tracking session through GridViewController and then exercising `shutdown`, `isEnabled=false`, `jumpTo`, or cancelled NSEvent. Consequently F1 passed all current tests.
