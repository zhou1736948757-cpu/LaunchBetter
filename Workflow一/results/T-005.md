# T-005 Result — P0 PageVisual compositor placement coordinates

## Outcome

Confirmed and retained the canonical placement-stage fix in `GridViewController`: the compositor placement now constructs the complete grid-content document rect with `leadingDocumentOffset`, `page * pageWidth`, `geometry.gridOrigin.x/y`, and `visual.logicalBounds`, then converts the complete rect with `collectionView.convert(documentRect, to: view)`. `PageVisual.logicalBounds` and renderer semantics were not changed.

The placement expression adds `gridOrigin.x/y` exactly once. The existing `leadingDocumentOffset` remains a separate physical-section offset and is also applied exactly once.

## Changed files

- `Packages/LaunchUI/Sources/LaunchUI/GridViewController.swift`
  - P0 placement construction is the canonical owner of the coordinate correction.
  - Uses a complete document rect and full-rect view conversion.
  - No changes to renderer or `PageVisual` semantics.
- `Packages/LaunchUI/Tests/LaunchUITests/PageCompositorGridIntegrationTests.swift`
  - Added/retained real compositor layer-frame assertions using independently calculated expected document rects and `collectionView.convert(..., to: view)`.
  - Covers page 0→1, middle page 1→2, middle→last page 2→3, and a leading-surface case proving the leading document offset is applied once.
  - Corrected the test helper to match the installed Swift Testing `#expect` API.

No other production files were changed for T-005. Existing unrelated uncommitted worktree changes were left untouched.

## Evidence

- The T-005 integration test asserts each active compositor layer's `minX`, `minY`, `width`, and `height` against an independently calculated expected frame, not merely layer count, opacity, or page index.
- The expected rect includes nonzero `geometry.gridOrigin.x/y` and is converted through the real collection-view/view hierarchy.

- The leading-surface scenario passed with `leadingDocumentOffset == geometry.pageWidth`, validating no leading offset off-by-one or double application.
- `PageVisualRenderer` still returns `logicalBounds.origin == .zero`; no renderer or logical-bounds semantics were altered.

## Deviation / test correction

An initial version of the new test additionally compared the full compositor grid-content layer's `minY` to the first cell's `minY`. That was an invalid assertion: the layer represents the complete grid-content rect while the real cell frame has different vertical coordinate semantics in the AppKit collection layout. The independent full-rect assertion required by T-005 remained, and the invalid cross-check was removed. The final behavior test passes and directly verifies the required placement coordinates.
