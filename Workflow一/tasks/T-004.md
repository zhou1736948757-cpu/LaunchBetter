# T-004: 全量验证与探针运行

## Task ID: T-004
## Priority: P0
## Status: READY (依赖 T-001, T-002, T-003)

## Objective

在 T-001、T-002、T-003 完成后，执行全量验证，确认所有验收标准满足。

## Scope

### 验证步骤

1. Git 状态核对：
```bash
git status --short --branch
git rev-parse HEAD
```

2. 全量测试：
```bash
swift test --package-path Packages/LaunchCore
swift test --package-path Packages/LaunchUI
swift test --package-path Packages/LaunchPlatform
git diff --check
```

3. Debug/Release 构建：
```bash
xcodebuild -project LaunchBetter.xcodeproj -scheme LaunchBetter build
xcodebuild -project LaunchBetter.xcodeproj -scheme LaunchBetter build -configuration Release
```

4. 探针运行：
- `--pagecompositor`
- `--pagingprobe`
- `--pagingstressprobe`
- `--pagingscrollprobe`
- `--pagingfeeltelemetry`（新增）

5. 手动验证路径（如环境允许）：
   1. show → idle → Page 1 → Page 2
   2. Page 2 → Page 1
   3. Page 1 → App Library
   4. App Library → Page 1
   5. 最后一页 → 前一页
   6. settle 中途反向
   7. 快速连续翻页
   8. compositor cache miss live fallback
   9. search/folder/settings/drag 期间禁止激活
   10. hide/show 后重新准备 Page 1 + Page 2

## Acceptance Criteria (全量)

1. Page 1 → Page 2 不再因 `currentPage == 0` 被结构性禁止启用 compositor。
2. 边界普通页只需 current + direction neighbor 两张视觉。
3. App Library 方向保持安全 live fallback。
4. 没有同步 PageVisual 渲染进入手势路径。
5. 没有新增 motion writer。
6. PageVisualCache 仍最多三张。
7. 默认产品路径不记录 compositor per-frame diagnostic events。
8. 默认产品路径不计算 compositor frame metrics。
9. 所有原有 paging interruption、offset ownership、blank-page 修复测试继续通过。
10. LaunchUI、LaunchCore、LaunchPlatform 全部通过。
11. Debug/Release 无新增 warning。
12. 没有修改公开 API。
13. 没有增加新的长期 owner 或 coordinator。
14. `git diff --check` 通过。
15. 未经真实触控板验证，不得宣称"主观丝滑问题已经完全完全解决"。
