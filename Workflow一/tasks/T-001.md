# T-001: 方向感知两页 PageCompositor + 第一页 PageVisual 准备

## Task ID: T-001
## Priority: P0
## Status: READY

## Objective

Compositor 不再要求三页视觉齐全。手势方向确定后，只需当前页和目标方向相邻页两张视觉即可激活。同时允许第一页（currentPage == 0）准备 PageVisual，使 Page 1 → Page 2 的第一次正常手势能命中 compositor。

## Design Constraints

1. 不得新增第二个 paging motion writer。
2. 不得让 PageCompositor 直接读取 Store、Grid、NSCollectionView 或 Paging 状态。
3. 不得在手势开始时同步渲染 PageVisual。
4. 缓存未就绪时必须立即 live fallback，不能阻塞手势。
5. 不得改变搜索、拖拽、Folder、Settings、App Library 的所有权。
6. 不得破坏 settle interruption。
7. 不得在 clip 已经离开页边界的 live settle 中途强行激活新 compositor。
8. 已经处于 active compositor 的 settle interruption 必须继续支持。

## Implementation Details

### PagingDirection

在 PagingInteractionController 内增加：

```swift
enum PagingDirection: Sendable, Equatable {
    case previous
    case next
}
```

### Direction Callback

```swift
var onWillStartHorizontalTracking: ((PagingDirection) -> Void)?
```

调用要求：
- 只在一次 tracking session 中调用一次。
- 必须已完成 axis lock。
- 必须有第一个非零水平 delta。
- 必须在第一次 tracking offset 写入之前调用。
- `deltaX < 0` 对应 next，`deltaX > 0` 对应 previous。
- 垂直手势、未定轴手势、零位移手势不调用。
- 不要用这个回调写 offset。它只允许 Grid 在第一次运动写入前切换 presentation surface。

### GridViewController 方向感知激活

将 `tryActivatePageCompositor()` 改为 `tryActivatePageCompositor(direction: PagingDirection)`。

激活条件：
- 当前 surface 必须是普通 layout page。
- current visual 必须存在。
- 目标方向相邻普通 layout page visual 必须存在。
- 如果目标是 App Library 或越界，返回 live fallback。
- 如果当前真实 offset 不接近页边界，且 compositor 当前没有 active，则返回 live fallback。
- 如果 compositor 已经 active，不重复激活。
- 页边界判断必须使用 page width 归一化，采用很小容差；不得使用硬编码像素判断。

### PageVisualCache 改造

新增针对明确页面集合的查询：

```swift
func visuals(
    for pages: [Int],
    displayRevision: UInt64,
    geometry: PageVisualGeometrySignature,
    backingScale: Int,
    languageRevision: UInt64
) -> [(page: Int, visual: PageVisual)]
```

要求：
- 返回顺序与请求 pages 一致。
- 任一页面缺失时，调用方可以明确判断不完整。
- 仍然忽略 iconEpoch，使用满足其他 key 条件的最后插入视觉。
- 保留现有最大三张 LRU 上限。
- 不引入新的缓存 owner。
- 旧的 three-page API 如有测试或其他调用方，可保留兼容包装。

### PageCompositor 两页支持

确认并测试：
- 两张 placements 可正常激活。
- layer frame 顺序稳定。
- finish、abort、shutdown 均正常。
- clip sync 后无残留 layer。
- live layer opacity 恢复为 1。
- 快速方向反转无跳变。

### performWorkingSetPrepare 修改

- 允许 `currentPage == 0`。
- 第一页准备 `[0, 1]`。
- 中间页准备 `[current - 1, current, current + 1]`。
- 最后一页准备 `[last - 1, last]`。
- 仍然逐页计算独立 iconEpoch。
- 仍然保留 displayRevision、languageRevision、geometry 和 backing scale 的最终复验。
- 仍然禁止在手势中同步光栅化。
- 仍然由已有 100ms debounce/idle 机制调度。
- 不要修改 hide 时的 PageVisual purge 策略。

## Acceptance Criteria

1. Page 1 → Page 2 不再因 `currentPage == 0` 被结构性禁止启用 compositor。
2. 边界普通页只需 current + direction neighbor 两张视觉。
3. App Library 方向保持安全 live fallback。
4. 没有同步 PageVisual 渲染进入手势路径。
5. 没有新增 motion writer。
6. PageVisualCache 仍最多三张。
7. PagingInteractionController 仍是唯一 motion writer。
8. settle interruption 不被破坏。
8. `advanceRealClipBehindCover()` 不得删除或改变其生产行为。
9. 搜索、拖拽、Folder、Settings、Library 所有权未改变。
10. 公开 API 未改变。
11. 没有增加新的长期 owner 或 coordinator。

## Required Tests

### PagingInteractionController
1. 水平轴锁定后，方向回调每次 gesture 只调用一次。
2. `deltaX < 0` 得到 next。
3. `deltaX > 0` 得到 previous。
4. 未定轴、垂直、零位移不调用。
5. settle interruption 后仍保持单一 writer。
6. live settle 中途且 offset 不在页边界时，不激活新的 compositor。
7. 已 active compositor 的 interruption 不被破坏。

### PageVisualCache
1. 请求 `[0, 1]` 能按顺序返回两张视觉。
2. 请求 `[1, 2]` 能按顺序返回两张视觉。
3. 缺任一视觉时不能误判完整。
4. displayRevision 不匹配时 miss。
5. geometry 不匹配时 miss。
6. backing scale 不匹配时 miss。
7. language revision 不匹配时 miss。
8. 多个 iconEpoch 匹配时仍取最后插入视觉。
9. 最大缓存数仍然不超过 3。

### PageCompositor
1. 两张 placements 可以 activate。
2. 两张 layer 的 offset 数学正确。
3. finish 后真实 clip 精确同步。
4. abort 后无残留 layer。
5. shutdown 幂等。
6. 快速方向反转无跳变。

### Grid 集成
1. 普通 Page 1 停留 idle 后能准备 `[0, 1]`。
2. Page 1 → Page 2 能激活两页 compositor。
3. Page 1 → App Library 走 live fallback。
4. 最后一页 → 前一页能激活两页 compositor。
5. 最后一页向越界方向稳定 fallback。
6. 中间页仍可使用三页缓存。
7. sparse page 仍按现有密度门 fallback。
8. 搜索、drag、Folder、Settings 状态下不得激活。
9. backing scale/data/language/geometry 变化后不得使用旧视觉。
10. compositor finish 后 live cell 已显示、opacity 为 1、无空白页。
11. paging offset ownership 仍只有 PagingInteractionController。
