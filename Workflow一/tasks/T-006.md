## Part A: P1 — Active compositor interruption 目标覆盖

### 问题

方向感知 compositor 只持有当前页和最初目标页。settle 中途同方向再滑动到第三页时，compositor 仍 active 但不包含第三页，live layer 隐藏，可能产生空白页。

### 修复策略（低风险）

为 `PageCompositor` 增加只读覆盖查询：

```swift
func covers(pages: Set<Int>) -> Bool
// 或
func containsPage(_ page: Int) -> Bool
```

不得让调用方依赖 `pageIndicesForDiag` 作为生产逻辑。

新手势到来且 compositor 已 active 时：

1. 根据最新 `currentPage` 和 `PagingDirection` 计算新目标。
2. 如果 active compositor 已覆盖当前页和新目标页 → 保持 active，不重建，记录覆盖复用结果。
3. 如果不覆盖新目标：
   - 在新手势第一次 offset 写入之前退出 compositor
   - 将真实 clip 同步到 `pageCompositor.currentOffset`
   - reveal live layer
   - 继续本次手势的 live fallback
   - 不同步渲染 PageVisual
   - 不阻塞等待 cache prepare

新增 activation result：`case activeCoverageMissing` 或 `case interruptionFallbackLive`

`PagingInteractionController.beginGesture()` 已从 compositor 读取 `baseOffset`。abort 同步的 clip offset 必须与 `pageCompositor.currentOffset` 相等，保证切回 live 时位置连续。

### Required Tests

1. Page 0→Page 1 settle 中途再向 Page 2 → 自动降级 live，clip 连续，无残留 layer，无空白。
2. Page 0→Page 1 settle 中途反向回 Page 0 → 已覆盖 [0,1]，继续复用，不 teardown/rebuild。
3. 末页附近中断场景。
4. Page 0→App Library 中断边界。
5. 新回调必须在第一次新 offset write 之前。

## Part B: P1 — 遥测格式化离开最终 DisplayLink 帧

### 问题

`flushGesture()` 同步执行 interval 数组复制、sorted()、reduce/p95/max、String(format:)、字符串插值，之后才异步 onSummary。格式化仍发生在最后一个 settle frame。

### 修复

1. 主线程只抓取一个不可变 Sendable snapshot。
2. 立即结束当前 telemetry session。
3. 在下一 runloop 或后台任务中格式化。
4. 最终回 MainActor 调用 onSummary。
5. 不允许后台任务读取或修改 telemetry recorder 可变状态。

定义：
```swift
struct GestureTelemetrySnapshot: Sendable
```

包含：gestureIndex, startPage, direction, firstGestureSinceShow, activationResult, cacheVisualCount, requiredPages, displayFrameCount, scrollWriteCount, settleDurationMs, interval samples, completionReason。

格式化函数必须是纯函数。

## Part C: P1 — interruption 前必须结束旧手势遥测

### 问题

新手势打断 settling 时，新的 beginGesture() 直接覆盖上一条记录。

### 修复

增加：
```swift
var onWillInterruptSettle: (() -> Void)?
```

由 PagingInteractionController 在以下时机调用：
- 确认旧 phase 为 `.settling`
- 在重置旧手势状态之前
- 每次 interruption 只调用一次

GridViewController 收到后：
- 记录旧手势最后的 frame/write 差分
- 记录 interruption completion reason
- flush 旧 gesture
- 然后才允许新手势建立新 telemetry session

摘要新增：`completionReason=settled|interrupted|cancelled|liveFallback`

## Part D: P1 — 分离两个诊断 flag

### 问题

当前 `--pagecompositor || --pagingfeeltelemetry` 让 telemetry flag 意外开启全部 compositor diagnostics。

### 修复

正确语义：
```
--pagecompositor
    开启 PageCompositorMetrics
    开启 PageCompositor events ring

--pagingfeeltelemetry
    开启 activation result
    开启真实 DisplayLink interval
    开启手势摘要
    不自动开启 PageCompositor 每帧 metrics/events
```

两个 flag 同时存在则同时开启。目标是让 `--pagingfeeltelemetry` 尽可能接近默认产品路径。

## Part E: P1 — firstGestureSinceShow 修正

### 问题

当前字段实际是 "first gesture since telemetry recorder initialization"。

### 修复

增加 `func beginShowSession()`，每次 launcher 真正 show 时调用，重置 `firstGestureSinceShow = true`。不在普通页面 refresh、settle 或搜索切换时错误重置。

如不愿修改 show 生命周期，则必须重命名为准确语义。优先选择真正实现 since-show。

## Part F: P1 — 激活原因修正

### 问题

1. Page 0 向 previous 时，无 App Library 的配置中不能记录 `.targetIsLibrary`。
2. `activate()` 后未确认 `isActive` 就记录 `.activated`。

### 修复

1. 正确区分 `.targetIsLibrary` 和 `.targetOutOfBounds`：
```swift
if leadingSurfaceEnabled && targetPage < 0 {
    .targetIsLibrary
} else if targetPage < 0 || targetPage >= pageCount {
    .targetOutOfBounds
}
```

2. `activate()` 后必须确认 `pageCompositor.isActive`，只有实际激活成功才记录 `.activated`。

3. 以下情况记录 `.invalidGeometry`：pageWidth <= 0, placements 为空, host/live layer 不存在, document rect 非 finite, activate 返回但 compositor 未 active。

## Part G: P1 — normalizedDamped 事件分片不变性

### 问题

每个 NSEvent 都执行 `followCurve.apply(rawDisplacement: deltaX, pageWidth:)` 后累加。非线性函数不可加，同样物理位移被分成不同数量 NSEvent 时得到不同结果。

### 修复

新增手势级累计原始位移：
```swift
private var rawTrackingDisplacement: CGFloat = 0
```

在 `beginGesture()` 重置。

对 normalizedDamped：
```swift
rawTrackingDisplacement += deltaX
let curvedTotal = followCurve.apply(rawDisplacement: rawTrackingDisplacement, pageWidth: pageWidth)
displacement = clamp(curvedTotal)
```

或保存上一次 curved total，计算 `appliedDelta = newCurvedTotal - previousCurvedTotal`。

必须保证：相同累计原始位移与事件如何切分无关。

### 默认 linear 路径保持

linear 路径继续：`displacement += deltaX * sensitivity`。不要为统一代码改变默认 linear 的浮点累加顺序。

不得改变：sensitivity 1.3, max gesture displacement, velocity estimator 输入, fling threshold, spring, rubber band。

### Required Tests

1. 一个 deltaX=200、两个 deltaX=100、十个 deltaX=20 → normalizedDamped 最终 displacement 一致。
2. mixed chunk: 50,30,70,50。
3. 正向、负向。
4. 中途反转: 100,100,-50,-150。
5. 60Hz/120Hz 等价事件序列。
6. 验证默认 linear 输出与修改前一致。

## Part H: P2 — 移除 public API 扩张

### 问题

`PagingFollowCurve` 在 LaunchCore 中是 public enum，改变了 LaunchCore 的 public API。

### 修复

优先方案：
- 将 `PagingFollowCurve` 移至 LaunchUI 内部
- 保持不依赖 AppKit，只依赖 Foundation/CoreGraphics
- 使用 `@testable import LaunchUI` 测试
- 类型和方法保持 internal
- 删除 LaunchCore 中对应的 public 类型和测试迁移残留

如因包依赖边界必须留在 LaunchCore，则必须明确承认这是 additive public API change。

优先保持公开 API 不变。

## Part I: P2 — 默认热路径小修复

### 问题

`PageCompositor.applyOffset()` 中，默认关闭 diagnostics 时仍每帧无条件构造 `.applied` 并调用 `recordEvent`。

### 修复

调用点 guard：
```swift
if diagnosticsEnabled {
    recordEvent(.applied(offset: offset))
}
```

不要为此重构 PageCompositor/PagingInteractionController/metrics 架构。
