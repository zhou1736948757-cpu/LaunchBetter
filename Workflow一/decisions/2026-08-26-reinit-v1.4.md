# Decision: Re-initialize workflow contract to v1.4 (2026-08-26)

## Context

The project was previously initialized with `chef-worker-reviewer-workflow` v1.1/1.3
(legacy "Chef" era). User requested re-creation of the workflow for the next
development phase on LaunchBetter (native macOS Launchpad alternative).

## Resolution 1: workflow artifact root

Both `.workflow/` (legacy, T-001..T-007 only) and `Workflow/` (superset, T-001..T-012
+ config/manifest) existed. User explicitly chose:

- `Workflow/` is the authoritative artifact root; continues to be used for all work.
- `.workflow/` is preserved untouched as legacy backup (byte-identical restore after
  initialization). It is untracked in git; no deletion planned unless user asks.

## Resolution 2: role model configuration

Existing config declared `openai-codex/gpt-5.6-luna` (opencode route ids) for
Chief/Worker/Reviewer. These ids are not routable from the current DSH harness.
User explicitly chose to reconfigure to the current session model.

- `models.main` = `current-main-conversation` (skill-sanctioned token; Main is this
  main conversation).
- `models.chief` / `models.worker` / `models.reviewer` = `current-main-conversation`
  (session-default model; DSH subagents inherit session routing by default).
- `max_worker_concurrency` = 3 (unchanged).
- `thinking_depth` = `high` (unchanged).

Caveat recorded per skill: the harness does not expose an exact model identifier
via environment/config to this session; these are declared identities of the
session-default model. Actual upstream routing is unverified. If dispatch-time
routing differs (harness rejection), stop and reconfigure — do not silently fall back.

## Semantics change (v1.3 → v1.4)

- v1.3: "Chief/Chef = current main conversation".
- v1.4: Main = current main conversation (Runtime center); Chief = persistent
  high-intelligence planning subagent; Worker/Reviewer as before; Expert Worker =
  temporary isolated Chief-class coder after second formal Reviewer FAIL.
