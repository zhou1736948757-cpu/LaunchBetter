## 事故描述

`v0.7.2` tag（36fdcb8）发布时**漏提交生产代码**：v0.7.1..v0.7.2 仅 3 个文件（AppCellFolderThumbnailLazyAllocationTests.swift、FolderThumbnailStyleConsistencyTests.swift、Workflow/reviews/T-022-r1.md）。T-020（AppCellView.swift + FolderThumbnailStyle）、T-022/T-023（PageVisualRenderer.swift 截断修复）、对应测试、pbxproj 版本号 bump、Workflow 记录全部未提交。

**后果**：tag 上 `FolderThumbnailStyleConsistencyTests` 引用不存在的 `FolderThumbnailStyle`（13 处）→ **GitHub v0.7.2 编译不过**；tag 上 MARKETING_VERSION 仍为 0.7.1。v0.7.2 从未有可用构建，用户侧零影响（无法安装），事故影响面为仓库与发布流程。

## 根因

1. `git add` 命令包含当时不存在的 pathspec（`Workflow/reviews/T-022-r1.md`，在 add 之后才创建）→ git add **整体失败**（pathspec 不匹配时 git add 不暂存任何文件）。
2. 错误输出被 `2>/dev/null` 吞掉 → 未察觉失败。
3. `git status --short` 的 ` M`（工作区已修改未暂存）被误读为暂存成功。
4. 后续补 add 只补了 2 个测试文件 + T-022-r1.md → commit 仅 3 文件。

## 修复（Chief 决策）

- **不移动已发布的 v0.7.2 tag**（历史记录保留）。
- **v0.7.3 补全发布**：生产代码 + 测试 + 版本号 0.7.2→0.7.3（0.7.2 从未有可用构建，跳号语义正确）+ Workflow 记录；commit message 写明事故。
- **发布验证门**（针对根因，T-024 固化为检查清单）：
  1. 暂存后：`git status --short` 确认无遗漏 + `git diff --cached --stat` 逐项核对
  2. commit 后 tag 前：`git show --stat HEAD` 复核
  3. tag 后：`git ls-tree -r v0.7.3 --name-only` 核对关键文件
  4. 最终门：`git clone --branch v0.7.3` 到 /tmp 全新目录 → Release build + 全量测试
  5. push 后：GitHub 确认 tag
- **过程禁令**：发布步骤中 git 命令禁止 `2>/dev/null` 吞错误；add 失败即停。

## 教训

1. git add 含不存在 pathspec 会整体失败 —— 发布前必须核对暂存区（`git diff --cached --stat`）。
2. 禁止用 `2>/dev/null` 吞 git 错误。
3. `git status` 的 ` M`（前导空格）≠ 已暂存；`M `（M 在前）才是。
4. 发布验证门（fresh-clone build+test）是防此类事故的权威手段。
