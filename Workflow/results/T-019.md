## 1. 根因复核（任务包 §2 逐条）

### Bug a — `drawCenteredText` 截断口径（任务包约 :566，实际 :569/:582）

| 项 | 复核结果 |
|---|---|
| 代码现状 | `PageVisualRenderer.swift:569` 超宽判断与 `:582` 居中计算均用 `CTLineGetBoundsWithOptions(line, [.useGlyphPathBounds])` ✅ 与任务包一致 |
| live 基准 | `AppCellView.swift:293-294`：`label.lineBreakMode = .byTruncatingTail` + `maximumNumberOfLines = 1`；标签矩形 = 单元格宽 −4（leading+2/trailing−2，:306-307）与 rasterize `labelRect`（cellFrame.width−4）一致 |
| 实证（探针，/tmp/ctline_probe*.swift，Swift 6.3.3/CoreText） | ① `CTLineGetBoundsWithOptions(line, [])`（默认）= `CTLineGetTypographicBounds` **逐位相等**（"Trailing Space Test "：typo=94.307，default=94.307，glyphPath=90.322，optical=91.377）；② `[.useGlyphPathBounds]` 系统性偏小（含尾随空格差 ~4pt，纯字母差 ~1.2-1.6pt）；③ **`CTLineCreateTruncatedLine` 截断决策边界 = typographic 宽度**（308.823pt 行在 308.813 截断、308.823 不截断；结果行 typo ≤ 请求宽度；宽度 < 省略号宽 ~6.49pt 时返回 NULL） |
| 结论 | 任务包根因成立：glyph-path 口径偏小 → `bounds.width > rect.width` 不触发 → 长名不截断（画全名、无省略号），与 live 不一致 |

### 1.2 Bug B — 文件夹尺寸（请求 :155 + 绘制 :450）

| 项 | 复核结果 |
|---|---|
| 代码现状 | `:155` `FolderThumbnailMetrics(side: geometry.cellSize)` ✅ 与任务包一致；另发现绘制侧 `:450` `side = min(frame.width, frame.height)` = cellSize 整格 —— **用户可见尺寸由此决定** |
| live 基准 | `AppCellView.swift:634-637` 请求用 `metrics(iconPointSize)`；`:767` 缩略图容器 side = `min(bounds)`，容器 frame = iconPointSize 正方形（`:336-352`）→ **live 请求与绘制同用 iconSize** |
| 真实几何 | `GridViewController.swift:338-341`：`cellSize = store.iconSize + 28`、`iconSize = store.iconSize` → **真实 app 中 cellSize 恒 ≠ iconSize**（分页压缩时也保持 chrome 差） |
| 结论 | 任务包根因成立；且复核发现"文件夹变大"需同时修 :155（请求口径/缓存身份）与 :450（绘制尺寸）两层 —— R2 授权后一并修复 |
