### 2.2 关键实现决策（deviations 之一，任务包 §5.3 明示允许）

**必须直接渲染 compositor 子层，而非 `hostLayer.render(in:)`**。探针实验（/tmp 独立脚本，
与 T-016 calayer-flip-experiment 同法）证实：

```
A direct flipped=true : top=blue bottom=red   ← 镜像（复现 T-016 实验）
B host+sub flipped=true : top=red bottom=blue ← 与 C 相同！
C host+sub flipped=false: top=red bottom=blue ← 无镜像
```

即 `CALayer.render(in:)` 的**软件渲染路径不应用子层 `isGeometryFlipped`**（host+sub 渲染在
flipped=true/false 下输出相同）。若渲染 host 层树，测试在修复前后都通过 —— 正是任务包
§5.3 警告的"测试永远通过"假阳性（首次尝试即命中，见 §3 失败证据）。直接渲染 compositor
子层才复现镜像机制（与 T-016 实验一致），任务包 §5.3 明示"或渲染 compositor 子层"。

## 6. Deviations

1. **渲染目标选择**：任务包 §5.3 允许 `hostLayer.render(in:)` **或**渲染 compositor 子层。
   实测 `hostLayer.render(in:)` 软件渲染不应用子层 `isGeometryFlipped`（探针 A/B/C 对比），
   渲染 host 层树会导致测试假阳性（修复前即通过）。故按任务包允许项改为**直接渲染
   compositor 子层**（`host.sublayers?.first`），与 T-016 calayer-flip-experiment 同法。
   已在测试注释（:575-583）与 §2.2 记录。
2. **测试断言范围**：标签白字断言限定 cell0 标签区（x 2..58）—— item0 用真实图标（无首
   字母），该区域唯一白字来源是标签；镜像时该区域是红色图标，断言必失败（避免被镜像后
   的占位首字母误满足）。
3. 其余无 deviation；方案 A 未破坏隐藏依赖，未触发方案 B。
