## 2. 脚本设计（scripts/verify-release.sh）

### 2.1 六道门（按序，逐门报告）

1. **working tree clean**：`git status --porcelain` 仅允许白名单条目（见 §2.3）；白名单外任何 M/D/A/R/C/?? → 大声失败（打印违规条目）
2. **tag exists**：`git rev-parse --verify <tag>` 本地存在 + `git ls-remote --tags origin <tag>` 已推送 + **本地与 origin SHA 一致**（防 tag 指向错误提交）
3. **fresh checkout**：`git clone --branch <tag> --depth 1` 到 `/tmp/lb-release-verify-<tag>-<pid>` 唯一目录
4. **version == tag**：clone 内 `project.pbxproj` 的 MARKETING_VERSION（全部取值须一致）== `<tag 去 v>`
5. **Release build**：`xcodebuild -project LaunchBetter.xcodeproj -scheme LaunchBetter -configuration Release -derivedDataPath <tmp>/derived build` → exit 0 且输出含 BUILD SUCCEEDED
6. **tests**：LaunchUI + LaunchCore + LaunchPlatform 全量（`CLANG_MODULE_CACHE_PATH=/private/tmp SWIFTPM_MODULECACHE_OVERRIDE=/private/tmp`），每包 exit 0 且 executed > 0（解析 `Test run with N tests`）

### 2.2 脚本纪律（事故根因对应）

- **无任何 stderr 吞错**：全脚本无 `2>/dev/null`（grep 验证 0 处；唯一历史匹配是注释，已改写措辞消除误报）；错误输出原样保留
- `set -euo pipefail` + 每门显式 exit code 检查（`if cmd; then :; else rc=$?; ...` 模式，避免 `if ! cmd` 分支取不到真实退出码）
- 参数校验：缺参/多参 → usage 退出 2；tag 非法字符 → 退出 2
- `trap EXIT` 删除自己的 /tmp 目录（`VERIFY_RELEASE_KEEP_TMP=1` 可保留，调试用）
- 失败时 `show_tail` 当场打印日志末尾（trap 会删日志，关键错误信息必须可见）
- bash 3.2 兼容（macOS 默认）：规避 `local x="$(cmd)"` 掩码退出码陷阱（先声明 local 再赋值 + `|| die`）

### 2.3 白名单（发布提交边界外 / 运行时状态）

- **未跟踪路径允许存在**（隐私目录 / 进行中工作流产物 / 验证门自身）：`Workflow/evidence/`、`Docs/aegis/`、`Workflow/tasks/`、`Workflow/results/`、`Workflow/reviews/`、`Workflow/decisions/`、`Workflow/incidents/`、`Workflow/review-bundles/`、`Workflow/watchdog.json`、`Workflow/watchdog-alerts.jsonl`、`Scripts/verify-release.sh`、`Workflow/RELEASE-CHECKLIST.md`

白名单依据事故记录"提交边界"（不纳入：evidence/、Docs/aegis/、B-REBUILD.md）+ 工作流进程层。白名单外任何条目 → 门 1 大声失败。
