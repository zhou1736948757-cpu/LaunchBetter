## 1. 目标

为分页滑屏实现一个**默认关闭**的性能诊断模式，flag：`--paging-perf`。若项目已有适合的诊断开关/格式可复用，但 Worker 必须说明实际启用命令和兼容性。

诊断模式必须具备：
- 每次 interaction session 的稳定 `sessionId`；
- 可聚合的 count / total duration / max duration；
- 单次 gesture / settle 的 session summary；
- 默认关闭时接近一次布尔判断的开销；
- 不改变原有 offset writer、状态机、布局、动画和产品交互；
- 输出不得逐帧刷屏；推荐在 session 完成时输出结构化 JSONL 摘要。

## 3. 必须区分采集的指标

### A. Interaction / Display Link（每 session）

- session id；gesture begin / horizontal axis lock / gesture end；settle start / settled / interrupted / cancelled
- 输入事件数；axis lock 前没有进入 displacement 的 event count 与累计 deltaX
- tracking frame 数；settling frame 数；总 display-link frame 数
- tracking、settling、总时长；`applyScroll` 调用数
- 实际 offset write 数；settle skip write 数
- 起始页、目标页、起始 offset、最终 offset；compositor 是否 active
- 若可低成本取得：输入到下一次 offset apply 的延迟

### B. Live / Compositor offset 路由（分开统计）

1. **live tracking**：真实 clip `scroll(to:)` 次数、total/max duration
2. **live settling**：真实 clip `scroll(to:)` 次数、total/max duration
3. **compositor tracking**：`PageCompositor.applyOffset` 次数、total/max duration；实际真实 clip 写次数（如果有，必须如实记录）
4. **compositor settling**：layer apply 次数、total/max duration；`advanceRealClipBehindCover()` 调用数；因 gap 阈值跳过的次数；catch-up clip 写次数、total/max duration；catch-up gap 最大值
5. **compositor teardown**：finish / abort / shutdown 的原因；sync clip duration；`layoutSubtreeIfNeeded()` 是否执行及 duration；teardown total duration

### C. Layout（diagnostics 开启时）

- `PagingGridLayout.prepare()` count、total/max duration
- `layoutAttributesForElements(in:)` count、total/max duration；candidate item 数；返回 attributes 数
- `shouldInvalidateLayout(forBoundsChange:)` 调用次数；返回 true / false 次数
- 能合理关联时，附带 session id / phase
- **不得为了记录修改 layout invalidation 的真实行为**

### D. Cell / Icon 路径

定位真实 provider / configure / icon request 路径并记录：
- cell provider 调用数；cell configure 调用数；prepare-for-reuse 数（若低成本且存在）
- icon request 启动数；icon cache hit / miss 数（只有可可靠区分时才记录）
- 每项发生时的：当前 paging phase（tracking / settling / idle）；compositor active 与否；session id 或明确的 idle 归属
- **不得声称** `clip.scroll(to:)` "必然物化 cell / 必然发 icon request"；本任务的运行时计数必须使真机 profile 能回答这个问题

## 4. 明确禁止项

- 不修改跟手、阈值、弹簧、边界橡皮筋、compositor gate、catch-up 比例
- 不重写 collection / scroll / clip 容器
- 不增加第二个 offset writer
- 不把一次 telemetry 任务夹带成分页机制重构
- 不修改搜索、拖拽、Folder、Settings、App Library 的产品行为
- 不改公开 API，除非测试 seam 必不可少；若有，必须在结果中说明兼容性
- 不删除历史 Reviewer FAIL；不修改 `Workflow一/`
- **不 commit / push / tag / release**；不清理工作树

## 6. 测试要求（真实执行，记录 exit code + executed/passed/failed）

1. **diagnostics off**：默认路径行为不变（全量回归 + 无 telemetry 输出）
2. **diagnostics on**：deterministic probe（测试 seam 驱动单次 gesture → settle → interrupted → cancelled 生命周期）生成 JSONL summary，字段齐全
3. **session 生命周期闭合**：normal settle / interruption / cancel 不丢失 session
4. 全量：LaunchUI 496/496+新增、LaunchCore 200/16、LaunchPlatform 149/23、git diff --check
- 禁止 exit 0 且 0 测试；SwiftPM 缓存报错用 CLANG_MODULE_CACHE_PATH=/private/tmp SWIFTPM_MODULECACHE_OVERRIDE=/private/tmp
- 本机后台负载高（用户任务在跑），测试可能慢，耐心等，不要误判超时

6. cell/icon 计数基于真实调用点，非推断
7. 无新 offset writer；无手感参数/容器/catch-up/gate 夹带改动
8. 测试覆盖 diagnostics off/on、interrupt/cancel、catch-up、teardown
9. T-013 保护条件零违反（paging 手感/compositor gate 零改动）
