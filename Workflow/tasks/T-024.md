# T-024 — 发布流程加固（verify-release.sh + 检查清单固化）

## 0. 基线快照

- git：`HEAD == origin/main == 190c604`（v0.7.3，tag v0.7.3 已推送，Release 条目已建）
- 事故背景：v0.7.2 发布漏提交生产代码（P0）—— 根因：git add 含不存在 pathspec 整体失败 + 2>/dev/null 吞错 + 误读 git status 工作区 M。事故记录：`Workflow/incidents/2026-08-27-v0.7.2-release.md`
- 测试基线：LaunchUI 489/489（67 suites）、LaunchCore 200/16、LaunchPlatform 149/23

## 1. 任务

把 v0.7.2 事故的验证门固化为可执行脚本 + 检查清单，防止复发。**不搞复杂 CI/CD**。

### 1a. `scripts/verify-release.sh <tag>`（核心交付）

一个极小的 bash 脚本，按顺序执行并逐门报告：

1. **working tree clean**：`git status --porcelain` 为空（或仅白名单未跟踪项）；不干净 → 大声失败
2. **tag exists**：`git rev-parse --verify <tag>` 成功；`git ls-remote --tags origin <tag>` 确认已推送
3. **fresh checkout**：`git clone --branch <tag> --depth 1` 到 /tmp 全新目录（每次用唯一目录名，如 /tmp/lb-release-verify-<tag>-<pid>）
4. **version == tag**：clone 内 `grep MARKETING_VERSION` 与 tag 名一致（v0.7.4 → 0.7.4）
5. **Release build**：`xcodebuild -project LaunchBetter.xcodeproj -scheme LaunchBetter -configuration Release -derivedDataPath <tmp>/derived build` → 必须 BUILD SUCCEEDED
6. **tests**：LaunchUI + LaunchCore + LaunchPlatform 全量（`CLANG_MODULE_CACHE_PATH=/private/tmp SWIFTPM_MODULECACHE_OVERRIDE=/private/tmp`），exit 0 且 executed > 0
7. 全部通过 → 打印 PASS 摘要；任一步失败 → 打印 FAIL + 步骤号 + 退出非零

**脚本纪律**：
- **禁止 `2>/dev/null` 吞错误**（事故根因）；错误输出保留
- 每步 `set -e` 语义（或显式检查 exit code）
- 脚本自身 `set -u`；参数校验（缺 tag 参数 → usage 退出）
- 清理：脚本结束删除自己的 /tmp 目录（trap EXIT）

### 1b. 发布检查清单（文档）

`Workflow/RELEASE-CHECKLIST.md`（或并入事故记录），固化人工步骤：

1. `git status --short` 确认无遗漏 M/?? 生产与测试文件
2. `git diff --cached --stat` 逐项核对暂存区
3. `git show --stat HEAD` commit 后复核
4. `git ls-tree -r <tag> --name-only` 核对关键文件
5. `scripts/verify-release.sh <tag>` 权威门
6. push 后 `git ls-remote --tags origin` 确认
7. GitHub Release 条目（notes 写明变更）
