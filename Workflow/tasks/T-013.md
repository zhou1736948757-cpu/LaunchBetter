## T-013-A：末页真实 active-settle interruption

目标：真实 GridViewController + PagingInteractionController + PageCompositor 验证：

Page 2 → Page 3 active compositor settle → deterministic mid-settle → 再向 Page 4 越界方向手势 → compositor 安全退出 → live fallback → 最终仍落在 Page 3 → 不生成 Page 4 visual → offset 连续且 live 非空。

修改现有 `boundaryInterruptionsUseLiveFallback` 或拆分为两个更明确的测试（推荐拆分）：
- `appLibraryBoundaryInterruptionUsesLiveFallback`（保留原 App Library scope 语义）
- `lastPageActiveSettleInterruptionUsesLiveFallback`（新末页真实中断）

### A1. 正确起点
从 Page 2 开始：`grid.goToPage(2, animated: false)`；等待 Page 2/Page 3 visual 准备完成；确认 `currentPage == 2`、cache 只含合法页、Page 3 visual 已准备、不存在 Page 4 key。

### A2. 启动真实 Page 2 → Page 3 compositor settle
发起能稳定解析到 Page 3 的 next 手势（非零位移）。手势结束后立即断言：phase == settling、pageCompositor active、active pages == [2, 3]、live layer 仍被 compositor 遮盖、settle target == Page 3（经 `pagingControllerForDiag` + `settleTargetPageForTest`）、没有 Page 4 visual。禁止离散跳转或直接调用 compositor.activate() 代替真实手势。

### A3. 推进到真正的 mid-settle
用 deterministic clock/probe display frame 循环推进（上限 1...60 帧），直到满足：phase 仍 settling、compositor 仍 active、`compositor currentOffset` 位于 2w 与 3w 之间且有明显余量：
- `lower = pageWidth * 2`、`upper = pageWidth * 3`；条件 `offset > lower + pageWidth * 0.1 && offset < upper - pageWidth * 0.05`
未达 mid-settle 前就 idle ⇒ 测试失败（不能把后续 idle gesture 当 interruption）。第二次手势前明确断言 phase/active/offset 区间/active pages == [2,3]。保存快照：`compositorOffsetBeforeInterruption`、`clipOffsetBeforeInterruption`、active layer identifiers、PageCompositor event counts、abort count、cache keys、cache visual count、visible item count。

### A4. 第二次向 Page 4 越界方向手势
settle 进行中发起第二次 next 手势（语义指向 Page 4/out-of-bounds）。PagingInteractionController 最终 settle target 可能 clamp 为 Page 3，但 Grid/PageCompositor 方向决策必须识别：current semantic page 已为 Page 3、direction == next、requested compositor target == Page 4、Page 4 不合法 ⇒ 立即 live fallback。禁止净位移为零输入；禁止最终回到 Page 2 的输入。

### A5. 中断瞬间断言
第二次手势触发后、推进新 settle frame 之前立即断言：compositor inactive；layer 已安全退出；live opacity == 1（或无 liveLayer 结构下明确证明 live 未被隐藏）；clip offset 与 abort 前 compositor offset 连续（小浮点容差）；visibleItemsCount > 0；cache visual count 不增；cache key 集合不增；无 pageIndex == 4；所有 page key 合法；无同步 PageVisual render/build；无等待 cache；abort event 恰好增加一次；不允许 shutdown/finishedSettle 冒充 interruption abort。若现有 seam 可断言 activation result 为 `.targetOutOfBounds`（或对应 fallback result）则直接断言。不为测试新增 public API；如需诊断 seam：仅 internal、只读、不写 motion、不改默认路径、opt-in/仅供测试，并先说明为何必要（由 Reviewer 判断）。

### A6. 最终落点
驱动新 settle 直到 idle。断言：`currentPage == 3`；clip offset == `pageWidth * 3`；phase == idle；compositor inactive；compositor layers 空；live 内容非空；visibleItemsCount > 0；无 Page 4 visual/cache key；无残留 active animator；无残留隐藏 live layer；无额外 abort/shutdown；只发生预期的 interruption teardown 与最终 settle。

### A7. 不允许的伪测试（以下不算 PASS）
从 Page 3 启动 Page 3→Page 3 零距离 settle；第二次手势前未断言 phase == settling；未断言 compositor active；只证明最终仍在 Page 3；只证明无 Page 4 cache key；净位移为零输入；纯 PagingInteractionController 单测代替 Grid+compositor integration；只检查 event string 不检查真实 compositor/live/clip 状态；只检查 visibleItemsCount 不检查 offset continuity；用 sleep 猜动画中点；修改生产 spring 参数让测试更容易通过。
