# 五、硬件与环境门

## 5.1 必须具备

关闭完整物理门至少需要：

- 一台真实 Apple Silicon Mac；
- 一块真实 Apple Trackpad：
  - MacBook 内置 Force Touch Trackpad，或
  - Magic Trackpad；
- 一个能够实际工作在 60Hz 的显示模式；
- 一个能够实际工作在 120Hz/ProMotion 的显示模式；
- 活跃 macOS WindowServer GUI 会话；
- LaunchBetter 可以接收真实滚动/手势事件；
- 测试操作者可以亲手完成手势。

优先使用同一台 Mac、同一显示器、同一触控板，在 60Hz 和 120Hz 间切换，
这样能减少机器、面板和输入设备差异。

## 5.2 不允许替代

以下不能关闭物理门：

- synthetic CGEvent；
- `pagingProbeGesture`；
- `probeDisplayFrame`；
- 单元测试；
- `--pagingscrollprobe`；
- `--pagecompositor` 自动 Probe；
- 录制后回放事件；
- 仅跑 60Hz；
- 仅验证显示器支持 120Hz，但没有实际切到 120Hz；
- 鼠标滚轮代替触控板。

鼠标可以作为补充兼容性测试，但不是 trackpad gate 的替代品。

## 5.3 缺设备时的状态

如果没有实际 120Hz 显示模式：

- 已完成的 60Hz 结果可以保存；
- T-016 最终 verdict 必须为 `BLOCKED`；
- `MANUAL_PHYSICAL_GATE` 保持 `OPEN / REQUIRED`；
- 不得写成 FAIL，因为缺设备不是产品失败；
- 不得写成 PARTIAL PASS 后关闭门。

# 十二、每个 Variant 的真实手势脚本

每个 variant 至少完成 24 个正式手势。

## S1 — 慢速跟手：6 次

- 手指持续接触触控板；
- 缓慢移动约 30%–70% 页面宽度；
- 观察页面是否稳定跟手；
- 交替完成 next 和 previous；
- 包含一次不足阈值后回弹；
- 包含一次越过阈值后 settle。

记录：

- 是否出现位置跳变；
- 是否出现起手延迟；
- 是否出现跟手比例突变；
- 手指停止时页面是否抖动；
- 回弹方向是否正确。

## S2 — 快速甩页：6 次

- 使用真实快速 flick；
- next/previous 各 3 次；
- 不连续狂甩，手势间等待 idle；
- 确认最终页目标正确。

记录：

- settle 是否顺畅；
- 是否错页；
- 是否出现空白页；
- 是否出现 live/compositor 切换 flash；
- 是否有明显停顿后突然追赶。

## S3 — settle 中反向接管：6 次

- 第一次 flick 触发 settle；
- settle 明显尚未结束时，立刻反向触摸并拖动；
- next→previous 与 previous→next 各 3 次；
- 必须是真实第二次触控板手势，不是 synthetic event。

记录：

- 第二次手势是否立即取得控制权；
- 是否发生 offset jump；
- 是否先完成旧 settle 再反向；
- 是否出现 compositor teardown flash；
- 最终目标页是否正确；
- telemetry completionReason 是否为 interrupted；
- 后一 session 是否独立。

## S4 — 边界场景：6 次

至少覆盖：

- 第一普通 Layout 页向 App Library 方向；
- App Library 返回第一普通 Layout 页；
- 最后普通 Layout 页继续向越界方向；
- 最后一页返回前一页。

记录：

- 是否正确 live fallback；
- 是否出现空白；
- 是否出现 Page N+1 假视觉；
- 是否卡在非整数 offset；
- 是否留下不可交互 layer；
- 后续正常翻页是否恢复。

总计：

- 每 variant 正式手势不少于 24；
- 每刷新率 4 variants，共不少于 96；
- 60Hz + 120Hz 共不少于 192 个正式手势。

鼠标测试另算，不得减少触控板样本数。

- frame interval sample count；
- avg；
- median；
- p90；
- p95；
- p99；
- max；
- nominal frame interval；
- interval > 1.5× nominal 的比例；
- interval > 2× nominal 的比例；
- activationResult 分布；
- completionReason 分布；
- fallback 分布；
- interrupted session 数；
- cancelled session 数；
- nil/缺失字段数；
- 每个 variant 的主观评分原始值与中位数；
- 每种二元缺陷出现次数。

名义帧预算：

- 60Hz：16.67ms；
- 120Hz：8.33ms。

必须同时分析：

- `/tmp/lb-paging-telemetry.log`；
- `--pagingfeeltelemetry` stdout summaries。

不能只读取每手势已经计算好的 p95 后再次平均；应尽可能保存并分析原始 session
与各手势统计，明确聚合方法。

如果当前日志没有逐帧原始 interval，只能使用已有 per-gesture summary，
必须把这一限制写进报告，不能伪称进行了完整 raw-frame distribution 分析。

# 十七、验收阈值

## 17.1 硬性正确性

以下任何一项可复现出现即不能关闭门：

- blank page；
- compositor/live reveal flash；
- visible offset jump；
- settle 后落错页；
- settle 中反向接管失效；
- 卡在非整数页；
- residual compositor layer；
- 输入持续被忽略；
- crash；
- telemetry session 串线；
- activationResult 与实际 variant 明显矛盾。

单次疑似人为误操作必须保留并重跑确认。

## 17.2 帧节奏

每个必测 compositor/default run：

- p95 不超过 nominal interval 的 1.5 倍；
- >1.5× nominal 的 interval 比例不超过 5%；
- >2× nominal 的严重 interval 比例不超过 1%；
- 不得出现重复、稳定、肉眼可感知的长停顿；
- 120Hz 模式不能持续呈现约 16.67ms 的 60Hz cadence。

如果 120Hz 显示模式已确认，但 LaunchBetter 稳定只能产生约 60Hz cadence：

- 120Hz gate = FAIL；
- 不得写成"120Hz-ready 已验证"。

## 17.3 Compositor 对照

在同刷新率、同曲线、同数据集下：

- compositor 不得比 live 对照的 p95 恶化超过 10%；
- compositor 不得增加 severe-jank ratio；
- compositor 不得产生 live 模式没有的 flash/blank/jump；
- dense page 下若 compositor 没有任何可测收益，可以记录为"无明确收益"，
  但不能仅凭无收益就立刻删除架构；
- 如果 compositor 明显更差，记录为后续 Chief 决策输入，不在 T-016 中改代码。

## 17.4 Follow curve

normalizedDamped 只有同时满足以下条件，才可以在未来单独提议设为默认：

- 60Hz 与 120Hz 均不出现正确性回退；
- 帧指标不比 linear 恶化超过 10%；
- 跟手即时性、反向接管、总体舒适度至少两项稳定优于 linear；
- 没有操作者报告 rubbery、迟滞或过度阻尼；
- 在 compositor ON/OFF 下结论方向一致，或差异有明确解释。

T-016 不得直接把 normalizedDamped 改成默认。

如果没有明确优势，保持 linear 1.3 默认。

# 十八、结果分类

Reviewer 最终只能返回：

- `PASS`
- `FAIL`
- `BLOCKED`

## PASS

只有以下全部成立：

- 60Hz 真实触控板完成；
- 120Hz 真实触控板完成；
- 设备/刷新率证据充分；
- 四 variants 均完成规定样本；
- 硬性正确性通过；
- 帧节奏阈值通过；
- compositor 对照无不可接受回退；
- telemetry 可解析且与场景一致；
- 主观评分完成；
- Reviewer 独立核验；
- 无生产代码修改。

此时可以写：

`MANUAL_PHYSICAL_GATE: CLOSED / PASS`

## FAIL

以下情况使用 FAIL：

- 具备硬件和权限；
- 测试真实执行；
- 出现可复现产品问题或阈值失败；
- Reviewer 可以将问题定位到具体 variant/gesture/refresh rate/log/video。

FAIL 后：

- 不在 T-016 内直接修代码；
- Main 整理失败包；
- 交给 Chief 决定是否创建生产 repair task。

## BLOCKED

以下情况使用 BLOCKED：

- 没有 120Hz 设备；
- 无法切换或证明实际刷新率；
- 没有真实触控板；
- GUI/WindowServer 不可用；
- 权限阻止真实输入；
- app 无法以 Release 交互式运行；
- telemetry 没有产生，且原因无法在不改生产代码的前提下解决；
- 样本不足；
- 视频/日志证据损坏。

BLOCKED 不是产品 FAIL。
