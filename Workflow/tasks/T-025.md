# T-025 — searchQuery 移出 LauncherStore（displayRevision 语义收敛）

## 0. 基线快照

- git：`HEAD == origin/main == 190c604`（v0.7.3）
- 测试基线：LaunchUI 489/489（67 suites）、LaunchCore 200/16、LaunchPlatform 149/23

## 1. 背景（GPT 分析 P1，Chief 采纳方向）

当前 `LauncherStoring` 定义 `var searchQuery: String { get set }`，`LauncherStore.searchQuery` didSet 里 `bumpRevision()` —— 输入 p/ph/pho/phot/photo 产生 5 个 displayRevision。问题：**search query 是 UI ephemeral state，被错误表达为整个 display model 的版本变化** —— 它不改变 Catalog/Layout/Folder/Icon/Geometry/Language，却使普通 PageVisual cache identity 失效（退出搜索后需重新准备 PageVisual）。

## 2. 方案（GPT 建议，严格按此）

```text
SearchField
   ↓
Grid search state（UI 层持有 query）
   ↓
Store.searchResults(for:)
   ↓
SearchIndex
```

- `LauncherStoring` **移除** `searchQuery` 属性（get set）
- `LauncherStore` 保有 SearchIndex，**不保有 query**
- 新增 `func searchResults(for query: String) -> [DisplayItem]`（或等价 API，以现有调用方为准）
- `displayRevision` 不再因搜索变化递增；搜索不使普通 PageVisual cache identity 失效
- 文档注释同步修正（"目录/布局/配置/搜索任一变化即递增" → 移除"搜索"）

### 允许/禁止
- 允许改：LauncherStoring/LauncherStore 及搜索相关调用方（GridViewController 等）、相关测试、Workflow 记录
- 禁止改：PageCompositor/PagingInteractionController/PageVisual 渲染路径（除非搜索过滤逻辑本身需要）；不得 commit/push/tag/release
- 注意：搜索过滤后的 grid 显示逻辑（searchResults 消费方）必须保持现有行为不变 —— 只改 query 归属与 revision 语义
