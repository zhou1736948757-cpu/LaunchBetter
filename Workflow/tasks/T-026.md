# T-026 — Wallpaper PNG 持久化移出 display-ready path

## 0. 基线快照

- git：`HEAD == origin/main == 190c604`（v0.7.3）
- 测试基线：LaunchUI 489/489（67 suites）、LaunchCore 200/16、LaunchPlatform 149/23

## 1. 背景（GPT 分析 P1，Chief 采纳方向）

当前 Wallpaper cold path：`render()` 成功后先 `cache[cacheKey] = rendered`（正确），但随后**同步**执行 `pngData(of:)` + `createDirectory` + `data.write(.atomic)`，全部完成后才 `return rendered`。即：CoreImage render 完成 → 已有可显示 CGImage → 却先做 PNG encode + mkdir + atomic write → 最后才给 UI。与 Icon pipeline 已采用的策略（memory cache → return → 后台持久化）不一致。Phase 4 已实测 cold launcher show 明显被 wallpaper 支配。

## 2. 方案（GPT 建议，严格按此）

```text
render
 ↓
memory cache
 ↓
return CGImage ─────────→ UI 显示

        ↘ utility serial writer
          PNG encode
          atomic write
```

- **不重构 Wallpaper 架构**：不需要 generic cache writer / actor graph
- 一个极小的 `WallpaperDiskWriter`（或 Provider 内专用 serial Task/queue）即可
- 持久化失败不阻塞 UI（后台写，错误记录不抛出）

### 允许/禁止
- 允许改：Wallpaper 相关文件（Provider/render 路径）、相关测试、Workflow 记录
- 禁止改：PageCompositor/PagingInteractionController/PageVisual 渲染路径；不得 commit/push/tag/release
- 注意：**不得声称性能收益**（除非实测）；本任务交付"结构正确 + 行为不变"

## 3. 测试要求（真实执行，记录 exit code + executed/passed/failed）

2. **UI 不阻塞**：render 返回不等待磁盘写（可用测试 seam 验证：写盘延迟不影响 return；或结构断言：写盘在 serial writer 中）
