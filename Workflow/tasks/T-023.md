## 1. 背景

T-022 Reviewer 发现 MAJOR：raster 截断实为**硬切**（`CTLineCreateTruncatedLine(line, width, .end, nil)` 本系统从不附加省略号 —— "Affinity Designer 2.6"@96.5 → "Affinity Designer 2." 92.24pt），live 是真省略号（"Affinity Designer 2…" 88.5pt）→ 全名 bug 已修但省略号两态出现/消失。Chief 决策采纳 (b) 显式 "…" token。

## 2. 修复方案（Chief 裁定，严格按此）

### 关键事实（Chief 实测）
`CTLineCreateTruncatedLine` 的 width 参数语义 = **结果行总宽上限（含 token）**，与 live NSTextFieldCell 的 "text+ellipsis ≤ frame−7.7" **同构** → **7.5 常量无需调整**（token@96.5 行宽 88.77/93.83pt ≈ live 88.5/93.5pt，Δ0.27/0.33pt 亚像素）。

### 实现（一行改动）
- `PageVisualRenderer.swift` `drawCenteredText` 截断分支：创建 token 行 `CTLineCreateWithAttributedString("…" U+2026, 与文本同 font/attributes)`，传入 `CTLineCreateTruncatedLine(line, width, .end, tokenLine)`（nil → token）
- **截断宽度不变**：`labelRect.width − 7.5`（96.5）
- 常量注释补充：width 参数含 token 总宽，与 live "text+ellipsis ≤ frame−7.7" 同构；实测 token@96.5 行宽 88.77/93.83 ≈ live 88.5/93.5
- 占位字母路径（truncatingTail:false）不受影响；文件夹标签同路径自动同修

### 允许/禁止
- 允许改：`PageVisualRenderer.swift`（仅 token 一行 + 注释）、`PageVisualRendererTests.swift`（测试更新）、`Workflow/` 记录
- **禁止改**：`AppCellView.swift`（live 路径）、`PageCompositor.swift`、PageVisualKey/缓存签名、其他生产/测试文件
- 不得 commit/push/tag/release（需 Main 确认）
