## 2. 第一阶段必须回答四个问题

### Q1. 用户看到的到底是哪一个字符串
记录：exact text、AppID/FolderID、app or folder、font（10pt?）、当前 cellSize、当前 iconSize。
（用户需提供具体 app 名；Worker 先用典型长名如 "Adobe Photoshop 2026" 做 probe，标注为占位输入）

### Q2. Raster 认为自己有多少宽度
读 `PageVisualRenderer.swift` drawLabel/drawCenteredText：
- 记录：string typographic width、labelRect width（cellFrame.width − 4）、wasTruncated、truncated line width
- 例：text="Adobe Photoshop 2026" typographic=104.3 rasterAvailable=96 wasTruncated=true

### Q3. Live 真正有多少"文字绘制宽度"
读 `AppCellView.swift` label 配置（:291-310）：
- 外层约束：leading=+2、trailing=−2（宽度 = cellWidth−4）
- **必须实测**：`label.bounds`、`label.frame`、`label.cell?.drawingRect(forBounds:)`、`label.cell?.titleRect(forBounds:)` —— 具体哪个 API 对当前 label-backed field 生效以实际 probe 为准
- **不要预先假定只差 1–2 px**：AppKit text-cell 内部 inset / glyph metrics 可能更大

### Q4. 直接检查 PageVisual.image（关键，不要从屏幕猜）
生成真实 PageVisual → CGImage 直接 ImageIO 保存 PNG → 观察该 app 的 label：
- **Case A**：raw PageVisual PNG 已正确显示省略号 → Renderer 没问题 → 查旧 cache / 实际用户看到的 surface / compositor 是否使用对应 PageVisual
- **Case B**：raw PageVisual PNG 仍完整名字 → 再看 typographic width <= raster width?
  - YES → live/raster effective width contract 不一致
  - NO → truncation implementation 仍有 bug
